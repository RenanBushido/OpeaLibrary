## Why

`src/` has already moved to a CQRS-shaped persistence split — `IBookRepository`/`ILoanRepository` were replaced by separate `IBookReadRepository`/`IBookWriteRepository`/`ILoanReadRepository`/`ILoanWriteRepository`, writes now live in Postgres (`BookWriteRepository`, `LoanWriteRepository`, exposed via `IUnitOfWork`) while reads moved entirely to MongoDB (`BookReadRepository`, `LoanReadRepository`), and DI registration moved out of `src/Application/DependencyInjection.cs` into a new `src/CrossCutting` project (`ApplicationExtensions`, `InfrastructureExtensions`) alongside a new `src/Presentation` API host — but `tests/` was never updated to match. `tests/OpeaLibrary.Infrastructure.Tests` fails to compile with 17 errors: `UnitOfWorkTests.cs`, `BookRepositoryTests.cs`, and `LoanRepositoryTests.cs` all reference the removed `UnitOfWork.BookRepository`/`LoanRepository` properties and call `GetBookByIdAsync` on `IBookWriteRepository` (which no longer has read methods), and `TestDbContextFactory.cs` calls `UseInMemoryDatabase`, an EF Core InMemory provider method that no longer resolves because the package reference is gone. The two OpenSpec capability specs governing these suites (`application-unit-tests`, `infrastructure-unit-tests`) still describe the pre-split combined-repository contracts and the EF InMemory testing strategy, so they no longer match either the code or (per Microsoft's own EF Core testing guidance, which discourages the InMemory provider) current best practice.

## What Changes

- **BREAKING**: Fix `tests/OpeaLibrary.Infrastructure.Tests` to compile against the split repository interfaces: replace all `unitOfWork.BookRepository`/`unitOfWork.LoanRepository` usages with `unitOfWork.BookWriteRepository`/`unitOfWork.LoanWriteRepository`, and stop asserting read behavior (`GetBookByIdAsync`, `GetAllBooksAsync`, `GetAllLoansAsync`) through the write repositories — those methods no longer exist there. Read-after-write assertions (e.g. confirming `RequestLoanAsync` decremented `QuantityAvailable`) now query the `OpeaLibraryDbContext` directly instead of going through a repository.
- Replace `TestDbContextFactory`'s EF Core InMemory provider (`UseInMemoryDatabase`, currently a compile error) with SQLite in-memory (`UseSqlite("DataSource=:memory:")`, connection kept open for the test's lifetime), per Microsoft's EF Core testing docs, which explicitly discourage the InMemory provider in favor of SQLite in-memory or the repository pattern. This keeps `BookWriteRepositoryTests`/`LoanWriteRepositoryTests` exercising real relational/EF query translation instead of the InMemory provider's divergent semantics.
- Rename `BookRepositoryTests.cs` → `BookWriteRepositoryTests.cs` and `LoanRepositoryTests.cs` → `LoanWriteRepositoryTests.cs` to match the renamed production types; scope their coverage to `BookWriteRepository`/`LoanWriteRepository` only.
- Add a new `BookReadRepositoryTests`/`LoanReadRepositoryTests` suite covering the MongoDB-backed `IBookReadRepository`/`ILoanReadRepository` implementations, run against an ephemeral, in-process MongoDB instance (new test-only dependency) rather than a live MongoDB server or a hand-rolled mock of `IMongoCollection`/`IFindFluent` (both are effectively unmockable through their extension-method-heavy driver surface).
- Add a `CrossCutting.Tests` xUnit project covering `ApplicationExtensions.AddApiMediatR`/`AddApiAutoMapper`/`AddApiValidators` and `InfrastructureExtensions.AddInfraPostgres`/`AddInfraMongo`, asserting each extension registers the expected services/lifetimes on an `IServiceCollection` and that the composed `ServiceProvider` resolves without error — this is the direct replacement for the deleted `tests/OpeaLibrary.Application.Tests/DependencyInjectionTests.cs`, which tested the now-removed `src/Application/DependencyInjection.cs`.
- Update `tests/OpeaLibrary.Application.Tests` fully onto the split interfaces: it largely already mocks `IBookReadRepository`/`IBookWriteRepository`/`ILoanReadRepository`/`ILoanWriteRepository` correctly (confirmed compiling with 0 errors), so this is a verification/cleanup pass, not a rewrite — mainly renaming `GetAllBookQueryHandlerTests` → `GetAllBooksQueryHandlerTests` to match the renamed `GetAllBooksQueryHandler`/`GetAllBooksRequest`/`GetAllBooksResponse` types.
- Update the `application-unit-tests` and `infrastructure-unit-tests` OpenSpec capability specs to describe the split read/write repository contracts, the SQLite in-memory strategy, and the new Mongo read-repository and CrossCutting DI coverage.

## Capabilities

### New Capabilities
- `crosscutting-unit-tests`: Automated xUnit test suite validating `src/CrossCutting`'s DI composition extensions (`ApplicationExtensions`, `InfrastructureExtensions`) — the correct registration of MediatR handlers/behaviors, AutoMapper profiles, FluentValidation validators, and the split Postgres/Mongo repository implementations.

### Modified Capabilities
- `infrastructure-unit-tests`: Now covers the split `BookWriteRepository`/`LoanWriteRepository` (Postgres, tested via SQLite in-memory instead of the EF Core InMemory provider) and the new `BookReadRepository`/`LoanReadRepository` (MongoDB, tested via an ephemeral in-process Mongo instance) — replacing the prior single combined-repository contract and its `100% coverage of src/Infrastructure/Persistence/Postgres/` scope, which is now split across two persistence technologies.
- `application-unit-tests`: Repository test doubles and coverage requirements now reference `IBookReadRepository`/`IBookWriteRepository`/`ILoanReadRepository`/`ILoanWriteRepository` instead of the removed `IBookRepository`/`ILoanRepository`; `GetAllBookQueryHandler`/`GetAllBookResponse` requirements are renamed to `GetAllBooksQueryHandler`/`GetAllBooksResponse`.

## Impact

- **Affected code**: `tests/OpeaLibrary.Infrastructure.Tests/TestDbContextFactory.cs`, `UnitOfWorkTests.cs`, `Repositories/BookRepositoryTests.cs` (renamed), `Repositories/LoanRepositoryTests.cs` (renamed); `tests/OpeaLibrary.Application.Tests/Books/Queries/GetAllBookQueryHandlerTests.cs` (renamed); `openspec/specs/application-unit-tests/spec.md`, `openspec/specs/infrastructure-unit-tests/spec.md`.
- **New code**: `tests/OpeaLibrary.Infrastructure.Tests/Repositories/BookReadRepositoryTests.cs`, `LoanReadRepositoryTests.cs`, a Mongo test-database fixture; a new `tests/OpeaLibrary.CrossCutting.Tests/` xUnit project.
- **New dependencies**: `Microsoft.EntityFrameworkCore.Sqlite` (test-only, `OpeaLibrary.Infrastructure.Tests`); an ephemeral/embedded MongoDB test package such as `EphemeralMongo6` or `Mongo2Go` (test-only, `OpeaLibrary.Infrastructure.Tests`); `Microsoft.NET.Test.Sdk`/`xunit`/`Moq`/`coverlet.collector` for the new `OpeaLibrary.CrossCutting.Tests` project, matching the other test projects.
- **Risk**: Purely test-suite and spec changes — no `src/` production code is modified by this change. The compile fix restores `dotnet test` to a runnable state across the solution; the SQLite/ephemeral-Mongo swaps change *how* persistence tests execute but not what they assert about existing, already-implemented behavior.
